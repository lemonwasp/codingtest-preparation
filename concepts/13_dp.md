# Dynamic Programming (DP)

## 한 문장

DP는 **이미 푼 작은 문제의 답을 저장해 두고, 그 답을 이용해서 더 큰 문제를 푸는 방법**이다.

## 왜 필요한가?

같은 계산을 계속 반복하면 비효율적이다.

피보나치를 재귀로만 풀면:

```text
fib(5)
├─ fib(4)
│  ├─ fib(3)
│  └─ fib(2)
└─ fib(3)
```

`fib(3)` 같은 계산을 여러 번 반복한다.

DP는 한 번 계산한 값을 저장한다.

```text
fib(3) = 2
```

다음부터 다시 계산하지 않고 꺼내 쓴다.

## 가장 중요한 질문

DP 문제를 만나면 먼저 이것부터 정한다.

> `dp[i]`가 무엇을 뜻하는가?

예:

```text
dp[i] = i번째 계단까지 가는 방법의 수
```

## 계단 예제

한 번에 1칸 또는 2칸 갈 수 있다고 하자.

5번째 계단에 오는 마지막 움직임은 둘 중 하나다.

```text
4 -> 5  (1칸)
3 -> 5  (2칸)
```

따라서:

```text
dp[5] = dp[4] + dp[3]
```

일반화:

```python
dp[i] = dp[i - 1] + dp[i - 2]
```

## 코드

```python
def climb(n):
    if n <= 2:
        return n

    dp = [0] * (n + 1)
    dp[1] = 1
    dp[2] = 2

    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]
```

## DP 문제를 푸는 순서

1. 상태 정의: `dp[i]`가 무엇인가?
2. 점화식: 이전 상태로 현재 상태를 어떻게 만들까?
3. 초기값: 가장 작은 문제의 답은 무엇인가?
4. 계산 순서: 필요한 이전 값이 먼저 계산되어 있는가?

## 다른 형태

최소 비용:

```python
dp[i] = min(dp[i - 1], dp[i - 2]) + cost[i]
```

최대 이익:

```python
dp[i] = max(dp[i - 1], dp[i - 2] + money[i])
```

## 언제 떠올릴까?

- 같은 작은 문제가 반복된다.
- 경우의 수를 센다.
- 최소/최대 비용을 이전 결과로 만들 수 있다.
- 완전탐색을 하면 경우의 수가 폭발한다.

## 기억법

> DP = 전에 푼 건 다시 풀지 말자.
